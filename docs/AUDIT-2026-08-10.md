- **Date:** August 10, 2026
- **Auditor:** Codex
- **Scope:** React frontend, Firebase Hosting, Firestore and Storage rules, Cloud
  Functions API, CI, dependencies, and a read-only production smoke check
- **Scoring basis:** Repository state after the remediations in this audit.
  Production observations describe the previously deployed state; this audit did
  not deploy changes.

## 1. Security

### Strengths

- Firebase ID tokens are verified server-side and role checks read authoritative
  Firestore data.
- API routes use rate limits, validation, and a shared error boundary.
- User-authored simulation code now runs in an opaque-origin `allow-scripts` iframe
  and parent messages are authenticated by the iframe window reference.
- Drive credential and sync routes now require admin authorization.

### Findings

| ID | Severity | Finding | Location |
| :--- | :--- | :--- | :--- |
| SEC-F01 | CRITICAL — fixed | `allow-scripts allow-same-origin` let untrusted preview code recover the parent origin and potentially access auth state. | `src/components/editor/SimPreviewFrame.tsx` |
| SEC-F02 | CRITICAL — fixed | A GitHub PAT could be read from a Firestore settings document whose rules allowed public reads. The code now accepts Secret Manager injection only and the document is explicitly denied. | `functions/src/routes/simulations.ts`, `firestore.rules` |
| SEC-F03 | HIGH — fixed | Any authenticated user could invoke Drive credential/import/sync operations. | `functions/src/routes/drive.ts` |
| SEC-F04 | HIGH — fixed | OAuth accepted ID tokens in query strings, did not enforce state expiry, trusted forwarded host for callback origin, and could encrypt an encrypted refresh token again. | `functions/src/routes/photosAuth.ts` |
| SEC-F05 | MEDIUM — open | App Check was returning 403/throttle warnings in production. A separate key is now required, but registration and enforcement must be verified after deployment. | `src/lib/firebase.ts`, Firebase console |
| SEC-F06 | MEDIUM — open | Hosting CSP still permits inline scripts/styles and lacks a stricter nonce/hash policy. | `firebase.json`, `index.html` |

## 2. Privacy & Youth Protection

### Strengths

- Name, email, and inquiry metadata are encrypted at rest with authenticated
  encryption; plaintext decryption is no longer retained in an unbounded cache.
- The public finance API returns a narrow transaction DTO without receipt URLs,
  logger identity, or raw Firestore documents.
- Inquiry reads are restricted to admin/coach roles in both API and rules.

### Findings

| ID | Severity | Finding | Location |
| :--- | :--- | :--- | :--- |
| PRIV-F01 | HIGH — fixed | Free-form inquiry metadata could contain phone, school, or message data in plaintext. | `functions/src/routes/inquiries.ts` |
| PRIV-F02 | HIGH — fixed | Direct public finance reads could expose receipts and internal user identifiers. | `functions/src/routes/finance.ts`, `firestore.rules` |
| PRIV-F03 | HIGH — fixed | Draft/deleted content was readable directly from several public collections. | `firestore.rules`, public page queries |
| PRIV-F04 | HIGH — operational | If the legacy PAT document existed while public settings rules were deployed, assume exposure and rotate it; rules cannot revoke a copied credential. | `docs/SECURITY_OPERATIONS.md` |

## 5. Code Efficiency

### Strengths

- Public finance reads are capped and cursor-compatible.
- Scheduled inquiry deletion now uses repeated batches of 400 instead of one
  unbounded read and an invalid over-500 write batch.
- Large uploads are authenticated and globally rate-limited before body parsing.
- Route-heavy tools are lazy-loaded; initial JavaScript is 1,176,767 bytes raw /
  358,361 gzip and initial CSS is 180,949 / 22,957 gzip.

### Findings

| ID | Severity | Finding | Location |
| :--- | :--- | :--- | :--- |
| EFF-F01 | HIGH — fixed | 10–50 MB bodies could be parsed before auth/router rate limiting. | `functions/src/index.ts` |
| EFF-F02 | HIGH — fixed | Cleanup loaded every expired inquiry and attempted one batch, failing above Firestore's write limit. | `functions/src/index.ts` |
| EFF-F03 | MEDIUM — open | Initial Firebase is about 171 KB gzip, and initial JS totals about 358 KB gzip. | production build output |
| EFF-F04 | MEDIUM — open | Monaco, Babel, and Prettier lazy chunks are very large; Monaco is about 718 KB gzip. | editor/simulation lazy routes |
| EFF-F05 | MEDIUM — open | Several realtime client queries remain broad and should gain limits/pagination or server aggregation. | public and dashboard Firestore queries |

### Findings

## 11. DevOps & Hygiene

### Strengths

  advisories remain.
- CI now blocks production high advisories and compiles Cloud Functions in the
  verification job.
- The bundle check now measures HTML-preloaded assets and the largest lazy chunk,
  instead of summing every route-lazy vendor as startup cost.

### Findings

| ID | Severity | Finding | Location |

## 12. Scalability & Resilience

### Strengths

- Bulk cleanup is bounded, transaction feeds are limited, and large request bodies
  are rejected before expensive parsing when unauthorized or over rate limits.
- Hosting uses immutable caching for hashed assets and no-store for HTML.

### Findings

| ID | Severity | Finding | Location |
| :--- | :--- | :--- | :--- |
| SCALE-F01 | MEDIUM — open | Express rate limits are per Functions instance and are not a distributed quota. | `functions/src/index.ts`, route limiters |
| SCALE-F02 | MEDIUM — open | Broad realtime listeners scale read cost with collection size and connected clients. | frontend Firestore queries |
| SCALE-F03 | LOW — open | Large simulation/editor dependencies cost substantial bandwidth when those tools are opened. | Vite chunks |

## Roadmap to compliance

### Must fix

1. Provision `GITHUB_PAT` and `PROFILE_SYNC_SECRET`, rotate the old GitHub token,
   and delete `settings/GITHUB_PAT` after verifying the new token.
2. Deploy Firestore rules, Storage rules, Functions, and Hosting as one coordinated
   release; smoke-test the six controls in `SECURITY_OPERATIONS.md`.
3. Add Firebase Emulator Suite allow/deny tests before any further rules expansion.

### Should fix

1. Correct App Check registration/key configuration, then enable enforcement in a
   staged rollout with monitoring.
2. Tighten CSP with hashes/nonces and add `object-src`, `base-uri`, `form-action`,
   Referrer-Policy, and Permissions-Policy where compatible.
3. Page or aggregate broad realtime queries and introduce distributed quotas for
   expensive endpoints.
4. Align developer workstations on Node 22.13+ and resolve Vite module mode.

### Backlog

1. Split components over 500 lines into screen sections and focused hooks.
2. Lazy-load narrower Monaco/Babel/Prettier features or move compilation work to a
   worker/server path where practical.
3. Add a focused WCAG audit for editor, graph, and canvas interactions.
